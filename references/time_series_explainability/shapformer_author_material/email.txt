We plan to share the ground truth generation code in a future version of the repository. I send you the corresponding files attached, so that you can already inspect and use them.

The procedure works as follows (your description is correct, but the following might help to understand the code):
- For creating a synthetic example, we sample the following features: a load profile (consisting of three daily load patterns for workdays, Saturdays, and Sundays/holidays), month, hour of day, day of week, holidays, and a temperature curve.
- The function generate_from_components() creates the ground truth load curve for the next week.
- PermutationSHAP creates alternative load curves for each feature coalition, by re-sampling the absent features and running generate_from_components() with the re-sampled features. It respects dependencies between features, e.g., the hour of day is not re-sampled when the day-of-week feature is known, because this would produce an unrealistic example where the hour-of-day-feature does not match with the day boundaries (and more dependencies, see the paper).
