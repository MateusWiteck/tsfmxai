What the pretraining sees

The series survives. The recipe does not.

  • Each stored record keeps only a start date and the target values
  • The kernel expression κ* is discarded
  • One training signal: predict the future from the context
The model never learns how a series was generated, and nothing is left to check an explanation against.
Official KernelSynth script (amazon-science/chronos-forecasting); Ansari et al., 2025, Section 3.3

T5

Raffel et al., 2020

Span corruption, and every task cast as text-to-text in one multi-task mixture

Several pretraining objectives shape a richer representation. We want the same for time series: today a forecaster is trained on essentially one task, predicting the future.
The second problem

Why did the model forecast that?

  • A foundation model returns a forecast, not a reason
  • Attribution methods such as SHAP can say which inputs mattered to the model
  • On real data the true cause is unknown, so we cannot tell whether an explanation is right
In a synthetic generator the mechanism is known, so the ground-truth explanation is exact.

Equation head = what computes the next step. Symbolic regression returns only the terms that really enter the formula, for example xₜ₊₁ = 0.6·xₜ − 0.3·xₜ₋₂. Lags that do not appear are not used directly.
future work Explanation head = what influenced the next step. It scores how much each past step shaped it, even a little and even without being in the formula: xₜ₋₁ is absent above, yet it shaped xₜ, which feeds xₜ₊₁. So it influences the next step, and through it, the whole future.
Problem 1: training. Extra pretraining tasks, in the spirit of BERT and BART, give the encoder a richer signal than forecasting alone.
Problem 2: explainability future work Exact ground-truth explanations make it possible to train and to verify explanations.
